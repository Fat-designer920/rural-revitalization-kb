## Phase A: QA助手做扎实（最优先，2周）

### A1. 检索升级 — 从TF-IDF到语义嵌入

**现状**: `scripts/npu_engine.py` 用 sklearn TfidfVectorizer char_wb(2,4)
**目标**: ONNX DirectML 运行 bge-large-zh-v1.5 嵌入模型

**改动文件**: `scripts/npu_engine.py`

**具体步骤**:
```
1. 下载模型: 从 HuggingFace 拉取 BAAI/bge-large-zh-v1.5
   → 用 optimum-cli export 转为 ONNX 格式
   → 放入 data/models/embedding_model.onnx

2. 修改 NPUEngine.__init__():
   - 检测 ONNX session 是否加载成功
   - 加载 tokenizer (用 transformers 或手动实现 vocab)
   - 备选方案: 若 model.onnx 不存在→回退 sklearn TF-IDF

3. 修改 build_index(texts):
   - 若 ONNX 已加载: 逐条encode→L2 normalize→np.array
   - 若未加载: 保持现有 char_wb TF-IDF

4. 新增 hybrid_search(query, texts, top_k=5):
   - Dense: ONNX embedding → cosine → top-50
   - Sparse: BM25 keyword (用现有TF-IDF) → top-20
   - Merge: 取交集+dense优先 → top-5
   - 若 ONNX 不可用→只用 sparse

5. 修改 semantic_search(): 调用 hybrid_search()
```

**验证标准**:
- `python -c "from scripts.npu_engine import NPUEngine; e=NPUEngine(); print(e.get_status()['onnx_model_loaded'])"` → True
- 50条中文测试查询, recall@20 > 85%
- smoke test 23 pass

**预估工时**: Claude 6-8小时(含模型下载转换调试)

### A2. 回答质量升级 — 4板块+老唐风格+溯源

**现状**: `scripts/qa_assistant.py` run_qa() 返回4板块,但检索用关键词LIKE
**目标**: 语义检索+老唐风格注入+每条引用可追溯

**改动文件**: `scripts/qa_assistant.py`, `scripts/prompts/prompt_templates.py`

**具体步骤**:
```
1. 修改 qa_assistant.py 检索层:
   - 替换 db.get_qa_retrieval_candidates(keywords) 
   - → 先用 NPUEngine.semantic_search() 取 top-50
   - → 再对 top-50 用 db 查完整 KP 字段
   - 保留原关键词检索作为fallback

2. 升级 QA_ANSWER_GEN_PROMPT(prompt_templates.py):
   - 在 system_prompt 中加入老唐身份锚点:
     "你是老唐——20年四川乡村振兴实战派。说话风格:直接、具体、不绕弯子。
      用乡镇干部能听懂的话讲清楚。不写学术论文,写操作手册。"
   - 强制输出格式:
     {
       "direct_answer": "≤400字直答(老唐风格)",
       "policy_basis": [{"kp_id": xxx, "title": "...", "excerpt": "..."}],
       "operational_steps": ["步骤1","步骤2","步骤3"],
       "risk_flags": ["风险点1"],
       "followup_questions": [...],
       "coverage_gap": "知识缺口声明/空字符串",
       "confidence": "high/medium/low/uncertain"
     }

3. 新增溯源展示逻辑:
   - answer_json 中 policy_basis 字段 
   - 前端渲染为可点击的引用链接

4. 新增"我不知道"边界:
   - 若检索结果 top-3 score < 0.15 → L3 规则兜底
   - 回答中 coverage_gap 必须写"此问题当前知识库无法充分覆盖"
   - 前端红色提示框显示
```

**验证标准**:
- 50条测试查询, answer 中 policy_basis 字段 non-empty > 80%
- "我不知道"触发率: 对明显超纲问题(如"月球土地政策")返回 uncertain
- smoke test 23 pass

**预估工时**: Claude 4-6小时

### A3. QA评测基线 — 200条测试集

**现状**: qa_history 19条, qa_feedback 0条
**目标**: 200条QA记录+评分基线, 老唐评50条黄金标准

**改动文件**: `scripts/qa_assistant.py`, `agents/kpi_tracker.py`

**具体步骤**:
```
1. 生成200条测试查询(Claude生成):
   5类各40条: 政策查询/实操方法/避坑指南/合规判断/项目策划
   覆盖四川高频场景: 增减挂钩/占补平衡/专项债/高标准农田/集体用地入市/林盘保护
   存储为 data/debug/test_queries_200.json

2. 批量运行QA:
   python -c "
   from scripts.qa_assistant import run_qa
   for q in queries:
       result = run_qa(q, mode='self', is_test_query=1)
       db.save_qa_history(...)
   "
   → 200条记录写入 qa_history

3. 自动评分(V4-Flash judge):
   维度: 准确性(1-5)/完整性(1-5)/可操作性(1-5)
   存储: qa_feedback 表, feedback_type='auto_score'
   → kpi_tracker.py 新增 qa_quality_metrics()

4. 老唐评50条黄金标准:
   从200条中抽样50条(每类10条)
   老唐评分: 1-5 + 写下"你认为的理想回答是什么"
   存储: qa_feedback 表, feedback_type='laotang_golden'

5. 计算检索质量:
   - recall@5/10/20 per category
   - 对比 NPU语义 vs 原关键词检索
   - 报告保存: logs/qa_baseline_report.json
```

**验证标准**:
- qa_history >= 200条
- qa_feedback >= 200条(auto_score) + 50条(laotang_golden)
- 检索 recall@20 数字可量化(知道当前是多少)

**预估工时**: Claude 3小时生成+运行+评分, 老唐 1.5小时评50条

**验证标准**:

## 依赖关系与并行策略

```
A1(检索升级) ──── 前置依赖 ──→ A2(回答质量) ──→ A3(QA基线)
                                      │
A4(反馈闭环) ←── 可并行 ──→ A5(落地页)    │
                                      ↓
                              Phase A完成 → 进入Phase B
                                              │
                              B1+B2+B3+B4 ←── 4线并行
                                              │
                                         所有产品上线
                                              ↓
                                         Phase C持续
```

**Phase A 内部并行**: A4+A5 可与 A1/A2/A3 并行(A4/A5不依赖检索升级结果)

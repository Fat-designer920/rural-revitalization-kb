# 乡村振兴知识库搭建助手 — SOP操作手册

> 版本：v1.0.0 | 适用对象：系统使用者（零编程基础）
> 本手册是日常操作的唯一参考，按场景编排，每步都有预期结果

## 第一章：系统介绍

### 1.1 这套系统能为我做什么

一句话概括：**你把原始资料丢进一个文件夹，AI帮你提取知识点，你审核确认后就变成了结构化的知识库。**

具体来说：

- 你有大量政策文件、项目案例、操盘笔记、合同模板、测算数据——散落在各种Word、PDF、Excel中
- 系统会自动识别文件类型，用AI提取出核心知识点（政策要点、案例数据、经验教训等）
- 你在本地网页界面中逐条审核、修改、确认
- 确认后的知识点存入本地数据库，形成你的专属知识资产

### 1.2 系统工作逻辑

```
你的操作                    系统自动完成                      结果
─────────────────────────────────────────────────────────────────
把文件放入 data/pending/    →  无需操作，等你启动             文件就位
双击"处理新文件.bat"        →  AI重命名+打标签+提取知识点     知识点入库（待审核）
双击"启动审核界面.bat"      →  打开本地网页                   你可以审核
在网页中审核每条知识点      →  你点"确认"或"忽略"             知识库更新
```

### 1.3 你的角色分工

| 你负责 | 系统自动完成 |
|--------|-------------|
| 把原始文件放进 data/pending/ 文件夹 | AI自动重命名文件、打标签 |
| 双击.bat文件启动各项操作 | AI自动读取文件内容、提取知识点 |
| 在审核界面中审核每条知识点 | 自动按文件类型选择对应Prompt |
| 决定"确认入库"还是"忽略" | 自动记录操作日志和API调用费用 |
| 修改AI提取结果中的错误 | 自动移动文件到对应阶段文件夹 |

## 第二章：首次安装配置手册

### 2.1 安装前准备

你需要准备：
1. 一台 Windows 电脑（Win10或Win11）
2. DeepSeek API Key（下面会教你申请）
3. 稳定的网络连接

### 2.2 完整安装流程

#### Step 1：解压系统文件

1. 把系统压缩包解压到你选择的位置（建议 `D:\知识库助手\`）
2. ⚠️ 路径中**不要有中文空格**，比如 `D:\我的 文件\` 这种不行
3. 解压后你会看到 scripts/、web/、bat/、data/ 等文件夹

**验证**：打开文件夹能看到 bat/ 目录下有多个 .bat 文件

#### Step 2：安装Python依赖库

1. 双击 `bat/安装依赖库.bat`
2. 会弹出黑色窗口，显示安装进度
3. 等待所有依赖安装完成，窗口会提示"安装完成"
4. 按任意键关闭窗口

**验证**：窗口中没有红色的 ERROR 字样
**常见卡点**：如果显示"pip不是内部或外部命令"，说明Python环境未正确配置，参见故障排查手册 #1

#### Step 3：申请 DeepSeek API Key

1. 打开浏览器，访问 https://platform.deepseek.com/
2. 注册账号并登录
3. 进入"API Keys"页面
4. 点击"创建 API Key"
5. 复制生成的 Key（以 `sk-` 开头的一长串字符）
6. ⚠️ 这个 Key 只显示一次，务必先复制保存到安全的地方

**验证**：你手上有一个以 `sk-` 开头的字符串

#### Step 4：运行配置向导

1. 双击 `bat/启动配置向导.bat`
2. 弹出图形化配置窗口
3. 在"DeepSeek API Key"输入框中粘贴你的 Key
4. "每日费用上限"保持默认50元，或者改为你希望的金额
5. 点击"保存配置"
6. 窗口提示"配置保存成功"

**验证**：`config/` 文件夹中出现了 `settings.json` 和 `encryption.key` 两个文件
**常见卡点**：如果窗口一闪而过，参见故障排查手册 #2

#### Step 5：初始化系统

1. 双击 `bat/初始化系统.bat`
2. 系统会自动创建所有必要的文件夹和数据库表
3. 窗口显示"初始化完成"
4. 按任意键关闭

**验证**：
- data/ 目录下出现 pending/、processing/、completed/ 三个子文件夹
- 根目录下出现 knowledge_base.db 数据库文件
- 桌面上出现快捷方式

#### Step 6：检查系统状态

1. 双击 `bat/检查系统状态.bat`
2. 系统会进行8项自检
3. 全部显示 ✓ 或 PASS 表示正常

**验证**：8项检查全部通过，没有 ✗ 或 FAIL

### 2.3 五个最容易卡壳的位置

| 位置 | 现象 | 解决方法 |
|------|------|---------|
| 安装依赖 | 显示 pip 不是内部命令 | Python环境未配置，参见故障排查手册 #1 |
| 配置向导 | 窗口一闪而过 | Python路径问题，参见故障排查手册 #2 |
| 初始化 | 报错"权限不足" | 右键.bat文件→以管理员身份运行 |
| 系统检查 | API连接失败 | 检查网络连接和API Key是否正确 |
| 处理文件 | 弹出费用上限提醒 | 正常保护机制，可在配置向导中调高上限 |

## 第三章：日常使用标准作业流程

### 场景A：我有一批新文件要处理

**目标**：把原始资料文件交给AI处理，提取出结构化知识点。

**Step 1**：把文件复制到待处理文件夹

1. 打开 `data/pending/` 文件夹
2. 把你要处理的文件复制进去
3. 支持的文件格式：PDF、Word（.docx）、Excel（.xlsx）、CSV、TXT、图片（.jpg/.png）

**预期结果**：文件出现在 data/pending/ 文件夹中

**Step 2**：启动处理

1. 双击 `bat/处理新文件.bat`
2. 黑色窗口会显示处理进度：
   - "正在预处理：xxx文件..." → AI给文件重命名+打标签
   - "正在提取知识点：xxx文件..." → AI按文件类型提取结构化内容
3. 处理完成后窗口提示处理结果统计

**预期结果**：
- data/pending/ 变空（文件已被移走）
- data/processing/ 中出现重命名后的文件（如果正在处理中）
- data/completed/ 中出现处理完成的文件
- 黑色窗口显示"处理完成，共提取 X 条知识点"

**Step 3**：检查处理结果

1. 查看黑色窗口中的统计信息
2. 注意是否有"跳过"或"失败"的文件
3. 按任意键关闭窗口

**注意事项**：
- 一次不要放太多文件，建议每批5-10个，避免费用超出每日上限
- 单个文件不要超过20MB
- 如果处理过程中网络中断，已处理的不受影响，未处理的留在原位，下次继续

---

### 场景B：我要审核AI提取的知识点

**目标**：逐条审核AI提取的知识点，确认无误后入库。

**Step 1**：启动审核界面

1. 双击 `bat/启动审核界面.bat`
2. 黑色窗口显示"Flask服务已启动..."
3. 浏览器自动打开 `http://127.0.0.1:5000`（如果没有自动打开，手动在浏览器中输入这个地址）
4. ⚠️ 黑色窗口不要关闭！关了审核界面就无法访问了

**预期结果**：浏览器中显示审核界面，上方有统计数字（待审核/已确认/已忽略）

**Step 2**：筛选知识点

1. 页面顶部有筛选栏：
   - 按分类筛选：选择"政策库"/"案例库"/"经验库"/"工具库"/"数据库"
   - 按状态筛选：选择"待审核"/"已确认"/"已忽略"
   - 按标签筛选：输入关键词
2. 默认显示"待审核"状态的知识点

**Step 3**：逐条审核

每条知识点显示以下信息：

| 字段 | 说明 | 你要关注什么 |
|------|------|-------------|
| 知识点标题 | AI生成的标题 | 是否准确概括了核心内容 |
| 原文摘录 | 从原文中截取的关键段落 | 对照原文确认提取是否准确 |
| AI提取内容 | 结构化的知识要点 | 重点审核，是否有遗漏或错误 |
| 建议分类 | AI建议归入哪个分类 | 分类是否合理 |
| 建议标签 | AI生成的关键词标签 | 可以修改或补充 |
| 原文路径 | 原始文件位置和页码 | 方便你回查原文 |
| 审核状态 | 待审核/已确认/已忽略 | 你的审核决定 |

**Step 4**：做出审核决定

对每条知识点，你有三个选择：

- **确认入库**：知识点准确，点击"确认"按钮 → 状态变为"已确认"
- **编辑后确认**：内容大致对但需要修改，点击"编辑"→修改内容→点击"确认"
- **忽略**：知识点没价值或提取错误，点击"忽略"→ 状态变为"已忽略"

**Step 5**：批量确认（可选）

如果某一批知识点质量都不错，可以勾选多条后点击"批量确认"按钮，一次性确认入库。

⚠️ 建议：前几批文件不要用批量确认，先逐条审核，了解AI的提取质量后再决定是否批量操作。

**Step 6**：结束审核

1. 审核完成后，直接关闭浏览器标签页
2. 回到黑色窗口，按 Ctrl+C 停止服务，或直接关闭窗口

### 场景G：系统崩溃后如何恢复

别慌，你的数据不会丢。按以下步骤操作：

**Step 1**：确认问题

先判断是什么情况：
- 双击 .bat 文件后窗口一闪而过 → 参见故障排查手册
- 审核界面打不开 → 可能是端口被占用，参见故障排查手册 #8
- 整个系统文件夹被误删 → 执行 Step 2

**Step 2**：从备份恢复（如有备份）

1. 重新解压一份系统压缩包到原来的位置
2. 从备份文件夹中复制回 `knowledge_base.db` 到项目根目录
3. 从备份文件夹中复制回 `config/settings.json` 和 `config/encryption.key`
4. 双击 `bat/检查系统状态.bat` 确认系统恢复正常

**Step 3**：从 GitHub 恢复代码（如无备份但有GitHub）

1. 打开 GitHub Desktop
2. File → Clone repository → 选择 `rural-revitalization-kb`
3. 代码文件全部恢复
4. 但 knowledge_base.db 和 config/ 不在 GitHub 中（被 .gitignore 排除了）
5. 如果数据库文件也丢了，很遗憾，知识库数据需要重新处理
6. 这就是为什么定期备份 knowledge_base.db 很重要

**Step 4**：验证恢复

1. 双击 `bat/检查系统状态.bat`
2. 8项检查全部通过
3. 双击 `bat/启动审核界面.bat`
4. 确认已确认的知识点数量与备份前一致

## 第四章：Prompt微调指南

### 4.1 什么情况下需要修改Prompt

当你发现以下现象时，可能需要调整 Prompt：

- AI提取的知识点总是遗漏某类重要信息（比如资金数据经常丢失）
- AI对某类文件的分类建议经常不准确
- AI的输出格式不符合你的使用习惯
- 你发现某个提取模板对特定文件类型效果不好

### 4.2 如何找到Prompt文件

所有 Prompt 模板集中在一个文件中：

```
scripts/prompts/prompt_templates.py
```

用记事本或任何文本编辑器打开即可。

### 4.3 修改Prompt的注意事项

⚠️ **修改前务必备份**：先复制一份 `prompt_templates.py` 改名为 `prompt_templates_备份.py`

**可以改的部分**：
- 引号内的中文提示词文字
- 要求AI关注的字段和重点
- 输出格式的要求

**不能改的部分**：
- 不要改变量名（等号左边的英文大写名称）
- 不要改代码结构（缩进、引号配对、函数定义）
- 不要删除 `{content}` 这个占位符——它是原文内容插入的位置

### 4.4 三个典型调整场景

**场景1：政策文件提取总是漏掉资金相关条款**

找到 `POLICY_EXTRACT_PROMPT`，在提示词中加入强调：

修改前：`"提取核心条款、执行要点、时间节点"`
修改后：`"提取核心条款、执行要点、时间节点、资金安排及来源（特别关注专项债、预算内资金等具体金额）"`

**场景2：案例提取的"创新点"总是泛泛而谈**

找到 `CASE_EXTRACT_PROMPT`，细化创新点的要求：

修改前：`"提取创新点"`
修改后：`"提取创新点（必须是该项目独有的、与常规做法不同的具体操作，而非笼统描述）"`

**场景3：文件重命名规则不满意**

找到 `FILE_RENAME_PROMPT`，调整命名格式要求。比如你希望文件名中包含地域信息：

修改前：`"[年份][类型]_[主题]_[来源]"`
修改后：`"[年份][类型]_[地域]_[主题]_[来源]"`

## 第五章：知识架构扩充操作指南

> ⚠️ 自动架构扩充建议功能将在 v1.1.0 加入。以下先说明手动操作方式。

### 5.1 什么是"架构扩充"

你的知识库有5大类、27个小类。随着业务发展，你可能发现：
- 有些新出的政策不好归入现有分类
- 某个二级分类下积累了太多知识点，需要进一步细分

这就需要"扩充架构"——增加新的二级分类。

### 5.2 当前版本的手动操作

v1.0.0 中如果你需要新增分类，请告诉 Claude：

"我需要在 [一级分类名] 下新增一个二级分类 [新分类名]，原因是 [为什么现有分类不够用]"

Claude 会为你生成数据库操作脚本，你按步骤执行即可。

### 5.3 v1.1.0 上线后的自动建议

v1.1.0 版本加入后，系统会在处理文件时自动检测：如果AI发现某批知识点不好归入现有分类，会在审核界面弹出"架构扩充建议"弹窗，你只需要点击按钮做决定即可。届时本手册会补充详细操作说明。

## 第六章：系统维护手册

### 6.1 每月检查清单

每月建议做一次系统体检：

| 检查项 | 操作 | 关注什么 |
|--------|------|---------|
| 系统状态 | 双击 `bat/检查系统状态.bat` | 8项全部通过 |
| 磁盘空间 | 查看项目所在磁盘剩余空间 | 至少保留1GB |
| 数据库大小 | 右键 knowledge_base.db → 属性 | 记录大小，超过500MB时告知Claude |
| API费用 | 登录 DeepSeek 控制台查看 | 月度费用是否在预期内 |
| 备份 | 执行场景F的手动备份 | 确认备份文件完整 |

### 6.2 如何更新Python依赖库

当 Claude 告诉你"需要更新依赖库"时：

1. 双击 `bat/安装依赖库.bat`
2. 它会自动更新所有依赖到 requirements.txt 中指定的版本
3. 等待完成，确认没有 ERROR

### 6.3 如何更换 DeepSeek API Key

当你的 API Key 过期或需要更换时：

1. 在 DeepSeek 控制台创建新的 API Key
2. 双击 `bat/启动配置向导.bat`
3. 在 API Key 输入框中粘贴新的 Key
4. 点击"保存配置"
5. 双击 `bat/检查系统状态.bat` 确认 API 连通性正常

### 6.4 如何迁移知识库到新电脑

**Step 1**：在旧电脑上备份

1. 把整个项目文件夹复制到U盘（包括 knowledge_base.db 和 config/ 目录）
2. 或者从 GitHub 克隆代码 + 手动复制 knowledge_base.db 和 config/

**Step 2**：在新电脑上恢复

1. 把项目文件夹复制到新电脑
2. 双击 `bat/安装依赖库.bat` 安装依赖
3. 双击 `bat/检查系统状态.bat` 确认正常
4. 完成

### 6.5 数据库容量注意事项

- knowledge_base.db 是 SQLite 文件，理论上支持到 140TB，日常使用完全无需担心
- 当文件大小超过 500MB 时（预计处理数千个文件后），可以告知 Claude，考虑归档旧数据
- 定期备份是最重要的，容量不是问题

## 第七章：常见问题 Q&A

### 基础操作类

**Q1：我可以一次处理多少个文件？**
技术上没有限制，但建议每批5-10个文件。主要考虑两点：一是API费用控制（每日上限默认50元），二是审核工作量。

**Q2：处理一个文件大概需要多长时间？**
取决于文件大小和内容复杂度。一般一个10页的PDF需要1-3分钟。网络不好时可能更长。

**Q3：支持哪些文件格式？**
PDF、Word（.docx）、Excel（.xlsx/.csv）、纯文本（.txt）、图片（.jpg/.png，通过OCR识别）。不支持 .doc（旧版Word）和扫描件质量很差的PDF。

**Q4：处理过程中可以关掉窗口吗？**
不建议。关掉窗口会中断当前处理。已处理完的文件不受影响，未处理的会留在 data/pending/ 中，下次再处理。

**Q5：审核界面可以同时在多个浏览器标签打开吗？**
可以，但不建议在多个标签页同时编辑同一条知识点，可能产生冲突。

### 知识提取类

**Q6：AI提取的知识点不准确怎么办？**
直接在审核界面中点"编辑"修改即可。如果某类文件的提取效果持续不好，参考第四章调整Prompt，或告诉Claude协助优化。

**Q7：同一个文件会提取出多少条知识点？**
取决于文件内容丰富程度。一个10页的政策文件可能提取3-8条知识点，一个50页的项目案例可能提取10-20条。

**Q8：超过8000字的长文件怎么处理？**
系统会自动分段处理。extractor.py 内置了分段逻辑，超长文件会被切分后分批发送给AI，最终合并结果。你不需要做任何额外操作。

**Q9：图片文件（扫描件）的识别效果如何？**
使用 DeepSeek 多模态OCR识别。清晰的扫描件效果较好，模糊或手写内容效果较差。建议先测试几张，效果不理想可以告知Claude切换OCR方案。

**Q10：我自己的笔记（非正式文档）能处理吗？**
可以。保存为 .txt 文件放入 pending/ 文件夹即可。系统会按"经验库"类型的 Prompt 处理。你也可以在文件名中加入提示，比如"经验_某某项目复盘.txt"，帮助AI更准确地选择Prompt。

### 数据安全类

**Q11：我的知识库数据会上传到云端吗？**
不会。所有数据存储在你电脑本地的 SQLite 数据库中。只有AI处理过程中，文件内容会发送给 DeepSeek API（通过HTTPS加密传输），处理完成后DeepSeek不会保留你的数据。

**Q12：API Key 是怎么保护的？**
API Key 通过 Fernet 对称加密后存储在 config/settings.json 中。即使有人看到这个文件，也无法直接获取你的 API Key（还需要 encryption.key 文件才能解密）。

**Q13：每日费用上限到了会怎样？**
系统会立即停止处理，弹窗提示"今日API费用已达上限"。已处理完的文件不受影响，未处理的留在 pending/ 中。第二天费用自动重置，可以继续处理。也可以在配置向导中调高上限。

### 维护升级类

**Q14：如何知道当前系统是什么版本？**
查看项目根目录下的 CHANGELOG.md 文件，最顶部的版本号就是当前版本。

**Q15：Claude更新了代码，我怎么替换？**
Claude 会给你完整的文件内容和保存路径。你只需要：找到对应文件 → 用新内容替换旧文件 → 保存。具体操作参见迭代升级手册。

**Q16：替换代码文件会影响我已有的知识库数据吗？**
不会。代码文件（scripts/目录）和数据文件（knowledge_base.db）是完全分离的。替换代码不会丢失数据。但替换前建议先备份，以防万一。

**Q17：Python版本需要更新吗？**
暂时不需要。系统基于 Python 3.8+ 开发，目前主流的 Python 3.10-3.12 都可以使用。除非Claude明确告知需要更新，否则不用管。

**Q18：处理新文件时报错"CostLimitExceeded"是什么意思？**
这是费用保护机制触发了。说明今天的API调用费用已经达到了你设置的每日上限。等明天费用重置后继续处理，或者在配置向导中调高上限。

**Q19：data/completed/ 里的文件可以删除吗？**
可以，但建议保留。这些是AI处理完成后的原始文件归档，万一将来需要重新处理某个文件，从这里找比较方便。如果磁盘空间紧张，可以将它们移到外部硬盘。

**Q20：如果我想处理一个已经处理过的文件怎么办？**
把文件从 data/completed/ 复制回 data/pending/，然后重新运行"处理新文件.bat"即可。系统会重新提取知识点（不会自动去重，需要你在审核时手动处理重复项）。

**Q21：.bat文件可以改名吗？**
不建议。.bat文件名是固定的，某些脚本之间有依赖关系。如果你想调整桌面快捷方式的名称，可以右键快捷方式→重命名。

**Q22：知识库数据能导出为Excel吗？**
当前版本暂未提供导出功能。如果需要，可以告诉Claude，这是一个小功能迭代，很快可以实现。

## #1 双击.bat文件后窗口一闪而过

**错误现象**：
双击任何一个 .bat 文件后，黑色窗口弹出又立刻消失，什么都没看到。

**原因分析**：
最常见的原因是 Python 环境路径没有正确配置，系统找不到 python 命令。

**解决步骤**：

1. 右键点击 .bat 文件 → 选择"编辑"（用记事本打开）
2. 查看文件中是否有类似 `python scripts\xxx.py` 这样的行
3. 打开命令提示符：按 Win+R，输入 `cmd`，回车
4. 在黑色窗口中输入 `python --version`，回车
5. 如果显示 `Python 3.x.x` → Python已安装，问题可能在路径设置上
6. 如果显示 `'python' 不是内部或外部命令` → Python未正确安装或未加入系统PATH
7. 解决方案：
   - 如果用的是嵌入式Python，确认 .bat 文件中的Python路径指向正确位置
   - 如果用的是系统安装的Python，重新安装时勾选"Add Python to PATH"
8. 修复后重新双击.bat文件测试

## #2 配置向导窗口弹出后立即崩溃

**错误现象**：
双击"启动配置向导.bat"后，弹出一个窗口但立即崩溃或报错。

**原因分析**：
通常是 tkinter 模块缺失（嵌入式Python可能未包含），或者 Python 版本过低。

**解决步骤**：

1. 打开命令提示符（Win+R → 输入 `cmd` → 回车）
2. 输入 `python -c "import tkinter; print('OK')"` 回车
3. 如果显示 `OK` → tkinter正常，问题在其他地方，把报错信息发给Claude
4. 如果显示 `ModuleNotFoundError: No module named 'tkinter'` → 需要安装带tkinter的Python
5. 解决方案：从 https://www.python.org/downloads/ 下载完整版Python安装包（不是嵌入式版），安装时确保勾选了 `tcl/tk and IDLE` 选项

## #3 安装依赖库时报错

**错误现象**：
双击"安装依赖库.bat"后，窗口中出现红色的 ERROR 或 Failed 字样。

**原因分析**：
可能是网络问题、pip版本过旧、或者某个依赖库与你的Python版本不兼容。

**解决步骤**：

1. 仔细查看错误信息，找到关键行（通常包含 `ERROR` 或 `Could not`）
2. 常见情况及对应处理：

**情况A**：`Could not find a version that satisfies the requirement`
→ 某个库版本不兼容。把错误信息发给Claude，Claude会调整 requirements.txt

**情况B**：`WARNING: pip is configured with locations that require TLS/SSL`
→ 网络证书问题。在命令行中尝试：
```
pip install -r requirements.txt --trusted-host pypi.org --trusted-host files.pythonhosted.org
```

**情况C**：`pip is not recognized as an internal or external command`
→ 回到 #1 的解决步骤，先解决Python环境问题

**情况D**：下载速度极慢或超时
→ 使用国内镜像源。在命令行中尝试：
```
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## #4 处理新文件时报错"API Key无效"

**错误现象**：
双击"处理新文件.bat"后，窗口显示类似 `API Error: Invalid API Key` 或 `Authentication failed`。

**原因分析**：
API Key 过期、输入错误、或者加密配置损坏。

**解决步骤**：

1. 双击 `bat/启动配置向导.bat`
2. 重新输入你的 DeepSeek API Key
3. 点击"保存配置"
4. 重新双击"处理新文件.bat"测试
5. 如果仍然报错：
   - 登录 https://platform.deepseek.com/ 检查Key是否有效
   - 如果Key已过期，创建新的Key
   - 确认账户余额是否充足

## #5 处理新文件时报错"CostLimitExceeded"

**错误现象**：
处理文件过程中，窗口突然停止并显示 `CostLimitExceeded: 今日API费用已达上限`。

**原因分析**：
这不是错误，是正常的费用保护机制。说明今天的API调用费用已经达到你设置的每日上限（默认50元）。

**解决步骤**：

1. 不需要修复，这是正常行为
2. 两种处理方式：
   - **等明天**：费用会在第二天自动重置，继续处理未完成的文件
   - **调高上限**：双击"启动配置向导.bat" → 修改"每日费用上限"为更高金额 → 保存 → 重新处理

**预防建议**：大批量文件分多天处理，每天5-10个文件。

## #6 处理新文件时报错"文件读取失败"

**错误现象**：
窗口显示 `FileReadError` 或 `无法读取文件: xxx`，某个文件被跳过。

**原因分析**：
文件格式不支持、文件损坏、或者文件被其他程序占用。

**解决步骤**：

1. 检查文件格式是否支持：PDF、.docx、.xlsx、.csv、.txt、.jpg、.png
2. ⚠️ 不支持的格式：.doc（旧版Word）、.xls（旧版Excel）、.ppt
3. 如果是 .doc 文件：用 Word 打开后另存为 .docx 格式
4. 检查文件是否被其他程序打开中（关闭Word/Excel后重试）
5. 检查文件是否损坏：尝试用对应软件正常打开一次
6. 检查文件大小：单个文件不要超过20MB
7. 修复后把文件放回 data/pending/，重新处理

## #7 处理新文件时报错"网络连接失败"

**错误现象**：
窗口显示 `ConnectionError`、`Timeout` 或 `Failed to connect to api.deepseek.com`。

**原因分析**：
网络不稳定、VPN干扰、或者 DeepSeek 服务暂时不可用。

**解决步骤**：

1. 检查电脑是否能正常上网（打开浏览器访问任意网站）
2. 如果使用了VPN，尝试关闭VPN后重试
3. 等待1-2分钟后重新运行"处理新文件.bat"
4. 系统内置了3次自动重试机制，间歇性的网络波动通常会自动恢复
5. 如果持续失败，可能是 DeepSeek 服务端维护，稍后再试
6. 已经成功处理的文件不受影响，未处理的文件留在 pending/ 中

## #8 审核界面打不开

**错误现象**：
双击"启动审核界面.bat"后：
- 黑色窗口提示"端口5000已被占用"，或者
- 浏览器显示"无法访问此网站"

**原因分析**：
端口被其他程序占用，或者Flask服务没有成功启动。

**解决步骤**：

**情况A**：端口被占用

1. 先关闭所有黑色命令行窗口
2. 打开任务管理器（Ctrl+Shift+Esc）
3. 在"详细信息"标签页中找到 `python.exe`
4. 右键 → 结束任务
5. 重新双击"启动审核界面.bat"

**情况B**：浏览器显示"无法访问"

1. 确认黑色窗口是否还在运行（不能关闭！）
2. 在浏览器地址栏手动输入 `http://127.0.0.1:5000`（注意是http不是https）
3. 如果还是不行，查看黑色窗口中是否有报错信息，截图发给Claude

## #9 审核界面中知识点显示为空或乱码

**错误现象**：
审核界面打开了，但知识点内容显示为空白、问号、或者乱码。

**原因分析**：
通常是数据库中的中文编码问题，或者 review.html 文件被错误修改。

**解决步骤**：

1. 在审核界面按 F12 打开浏览器开发者工具
2. 点击"Console"（控制台）标签页
3. 查看是否有红色报错信息，截图发给Claude
4. 如果是乱码问题：
   - 确认浏览器编码设置为 UTF-8
   - 清除浏览器缓存后刷新页面（Ctrl+Shift+Delete → 清除 → Ctrl+F5刷新）
5. 如果是空白问题：
   - 确认 data/pending/ 中确实处理过文件
   - 在审核界面的状态筛选中选择"全部"而非"待审核"

## #10 审核界面编辑保存失败

**错误现象**：
在审核界面中修改了知识点内容，点击保存后提示失败或没有反应。

**原因分析**：
可能是Flask后端接口异常，或者网络请求被拦截。

**解决步骤**：

1. 查看黑色命令行窗口中的日志信息（每个请求都会打印日志）
2. 刷新审核界面页面（F5），检查修改是否实际已保存
3. 如果确实没有保存成功：
   - 关闭审核界面
   - 关闭黑色窗口
   - 重新双击"启动审核界面.bat"
   - 重新编辑和保存
4. 如果持续失败，检查黑色窗口中的报错信息发给Claude

## #11 data/pending/ 中的文件没有被处理

**错误现象**：
双击"处理新文件.bat"后，窗口显示"没有发现需要处理的文件"，但 data/pending/ 里明明有文件。

**原因分析**：
文件格式不在支持列表中，或者文件名中包含特殊字符。

**解决步骤**：

1. 检查文件扩展名是否正确：
   - ✅ 支持：.pdf, .docx, .xlsx, .csv, .txt, .jpg, .jpeg, .png
   - ❌ 不支持：.doc, .xls, .ppt, .zip, .rar, .html
2. 检查文件名是否包含特殊字符：
   - ✅ 正常文件名：`增减挂钩政策_2025.pdf`
   - ❌ 问题文件名：`政策(最新版）[2].pdf`（中文括号、方括号可能有问题）
3. 尝试把文件重命名为简单的中文名称（避免特殊符号）
4. 重新运行"处理新文件.bat"

## #12 数据库文件损坏

**错误现象**：
启动审核界面或处理文件时，报错 `database is malformed` 或 `database disk image is malformed`。

**原因分析**：
SQLite数据库文件损坏，通常是因为处理过程中强行关闭电脑或窗口导致。

**解决步骤**：

1. ⚠️ 不要慌，先尝试修复：
2. 打开命令提示符（Win+R → cmd → 回车）
3. 切换到项目目录：`cd D:\GitHub\rural-revitalization-kb`（替换为你的实际路径）
4. 输入以下命令：
   ```
   python -c "import sqlite3; conn=sqlite3.connect('knowledge_base.db'); conn.execute('PRAGMA integrity_check'); print(conn.execute('PRAGMA integrity_check').fetchone())"
   ```
5. 如果显示 `('ok',)` → 数据库实际是完好的，问题在其他地方
6. 如果显示错误 → 数据库确实损坏，需要从备份恢复：
   - 找到最近的 knowledge_base.db 备份
   - 用备份文件替换当前损坏的文件
   - 备份之后新增的知识点会丢失，需要重新处理

**预防**：处理文件时不要强行关闭窗口或电脑。定期备份数据库。

## #13 系统检查显示某项FAIL

**错误现象**：
双击"检查系统状态.bat"后，某一项或多项显示 ✗ 或 FAIL。

**原因分析**：
取决于哪一项失败。

**解决步骤**：

| 失败项 | 可能原因 | 解决方法 |
|--------|---------|---------|
| Python检查 | Python未安装或路径错误 | 参见 #1 |
| 依赖库检查 | 某个库未安装 | 双击"安装依赖库.bat" |
| 脚本检查 | 某个.py文件缺失 | 从GitHub恢复或找Claude要 |
| 配置检查 | settings.json缺失 | 双击"启动配置向导.bat"重新配置 |
| 数据库检查 | .db文件缺失或损坏 | 双击"初始化系统.bat"或从备份恢复 |
| 文件夹检查 | data/子文件夹缺失 | 双击"初始化系统.bat"重建 |
| 磁盘检查 | 磁盘空间不足 | 清理磁盘，至少保留1GB |
| API检查 | 网络问题或Key无效 | 参见 #4 和 #7 |

## #14 GitHub Desktop 推送失败

**错误现象**：
在 GitHub Desktop 中点击 Push origin 后提示错误。

**原因分析**：
网络问题、GitHub 服务暂时不可用、或者权限问题。

**解决步骤**：

1. 检查网络连接
2. 点击"重试"按钮（Retry）
3. 如果提示 `Authentication failed`：
   - 点击 GitHub Desktop 菜单 → File → Options → Accounts
   - 重新登录 GitHub 账号
4. 如果提示 `remote rejected`：
   - 截图发给Claude，可能是仓库配置问题
5. 推送失败不影响本地代码和数据——你的本地提交是安全的，只是没同步到云端

## #15 处理大文件时系统卡住不动

**错误现象**：
处理某个特别大的文件（比如几十页的PDF）时，黑色窗口长时间没有新的输出。

**原因分析**：
大文件需要更长的AI处理时间。超过8000字的文件会被自动分段处理，每段都需要一次API调用。

**解决步骤**：

1. 先耐心等待。一个50页的PDF可能需要5-10分钟
2. 查看黑色窗口是否还有光标闪烁（说明程序仍在运行）
3. 如果超过15分钟没有任何输出：
   - 按 Ctrl+C 终止当前处理
   - 该文件不会被移走，下次可以重新处理
   - 考虑把大文件拆分为多个小文件后分别处理
4. 如果频繁遇到大文件超时，告诉Claude调整分段策略和超时时间

## 数据流

```
预处理: 原始文件 → 读取/OCR → .md 缓存(processing) + DB 记录
提取:   优先读 .md 缓存 → R1/V3 提取(v2.3.4 max_tokens=8192 + JSON Mode + JSON Lines 输出)
        → v2.3.4-hotfix1 五级降级链(段内同步,不留事后批量重跑):
          L0 R1 主提取 → L1 Kimi-K2.6 整段重提(硅基) → L2 R1 跨厂商镜像整段重提(硅基)
          → L3 F057 兜底(若 partial>=1) → L4 保留已提取 + ❌ 全失败
        → v2.3.4-hotfix3 BUG 修复:
          (a) `_is_thinking_model` 模式匹配 → 硅基思考型走 300s timeout(不再 120s 必超时)
          (b) 0 条 kp 未截断 + 解析成功 → 直接返回(不进降级链,背景段不浪费 token)
          (c) JSONL 0 行解析 → 自动降级到 7 步保险(救回 R1 偶发的 JSON 数组格式)
        → 每条 kp 入库带 extracted_by_model 字段(r1/kimi/r1_mirror/f057_recovery)
        → 文件级控制台输出 📊 [文件统计] 截断N/Kimi救M1/R1镜像救M2/F057兜底K/全失败J/耗时Ts/估算Y元
        → 归档 completed
质量链: 入库质检三级降级(F058) → 政策校验 → 重复检测 → 人工审核 → 专家注解 → 保鲜
补跑:   历史未质检 kp → 按文件分组 → 调 ext._quality_check 5 参 → 三级降级(F061)
        → 尾部自动调联动 qa≥4&draft → quotable (part3.2 预埋,v2.3.1 补齐)
批量:   批量勾选 → 版本重提取 → 自动去重联动(F059)
体检:   V3 全盘扫描 → 六维度报告(F048) → 低分打磨建议 → 逐条 Review → 喂料方向
        维度 5 无候选时前端明确告知"已跳过打磨"(part3.3,区分"没跑" vs "跑了但无可打磨")
        候选池允许 confirmed 条目进入(part3.4,修复全库 confirmed 后永久 100 分)
E2E:    路由自省 + 启动就绪 + AST 静态三维 + V3 事件语义(F062) → 四态 issue 跟踪 + 软提醒
        白名单基于 db_manager.py 真实行号(part3.3 刷新,67+11 条,行号漂移时必须重扫)
        issue 落库在 _save_report 后(part3.4,拿 report_id 后再 upsert,修复签名漂移)
        **诊断包导出(part3.5):报告弹窗一键生成 Markdown(按 rule_id+文件聚合 + 代码片段 + 事件摘要),发给 Claude 做异地诊断**
问答:   问题 → 关键词分词 → 精品+quotable 池检索 → V3 重排 → V3 4 板块生成
        三级降级链:V3 主链 → L1 重试 → L2 R1 兜底 → L3 规则兜底(F055,v2.3.2)
        朋友试用 ?mode=friend 隐藏元数据;老唐自测 is_test_query=1 不回写 used_count
```

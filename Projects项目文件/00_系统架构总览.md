# 系统架构总览

## 基本信息
- 当前版本：v2.0.0
- 封装方式：便携版（绿色免安装）
- 运行环境：Windows + Python 3.8+
- AI引擎：DeepSeek API（提取引擎使用R1推理模型，分类建议使用V3模型）
- 本地存储：SQLite
- 操作界面：Flask本地Web应用
- 操作方式：双击.bat文件
- 代码仓库：https://github.com/Fat-designer920/rural-revitalization-kb

## 系统定位
知识库是未来知识产品（B端付费内容 + C端问答助手订阅）的生产底座和核心护城河。
所有架构设计以"支撑高效变现"为终极目标。

## 三层标签体系（v2.0.0核心架构）
- 第一层：分类标签 — 6组41个固定标签，AI从清单中选，用于导航和AI检索过滤
- 第二层：属性标签 — 8个维度的限定选项，AI从候选值中选，用于精细画像
- 第三层：关键词 — AI自由提取5-15个，用于全文搜索和问答匹配
- 标签清单存储在 tag_config.py（代码层）+ tag_definitions表（数据库层），双重备份
- 横向拓展新业务领域 = 在A组增加标签，B-F组通用框架不变，代码不需要改

## 知识点元数据（v2.0.0新增）
- content_readiness：就绪度（草稿级/可引用级/精品级）— 控制产品质量
- source_authority：来源权威度（官方文件/行业权威/项目实证/业内交流）— 控制可信度
- access_level：变现分级（开放/标准/高级）— 预留，控制付费内容分发
- freshness_checked_at + freshness_interval_days：内容保鲜机制 — 防止引用过时信息

## 架构

用户操作层(.bat文件, GBK编码)
  |
Python脚本层(scripts/, UTF-8编码)
  |- config_wizard.py - tkinter配置向导
  |- setup.py - 一键初始化
  |- file_reader.py - 多格式读取
  |- deepseek_client.py - DeepSeek API封装
  |- preprocessor.py - 智能预处理
  |- extractor.py - 知识提取(R1+三层标签+AI分类建议)
  |- api_server.py - Flask审核界面(三层标签编辑+标签过滤+AI建议+全文搜索)
  |- db_manager.py - 数据库CRUD(13张表)
  |- tag_config.py - 标签体系配置(v2.0.0新增,独立于代码的标签清单)
  |- check_system.py - 系统检查
  |- prompts/prompt_templates.py - Prompt模板(适配三层标签)
  |- migrate_v110_to_v200.py - 数据库迁移脚本
  |
数据层(SQLite, 13张表)
  |- categories | source_files | knowledge_points(核心,含三层标签+元数据)
  |- knowledge_versions(预留) | architecture_suggestions | edit_history
  |- tag_definitions(v2.0.0) | knowledge_relations(v2.0.0) | knowledge_usage_log(v2.0.0) | tag_statistics(v2.0.0)
  |- operation_logs | api_call_logs | notion_sync_log(预留)

## 数据流
1. data/pending/ -> preprocessor(AI重命名) -> data/processing/
2. extractor(R1提取+三层标签+MD5去重) -> SQLite(待审核) -> data/completed/
3. 提取完成后 -> AI分类建议分析(V3) -> architecture_suggestions表
4. 提取失败 -> data/failed/(隔离)
5. api_server(审核界面) -> 人工审核(标签微调+就绪度+权威度) -> SQLite(已确认)
6. 已确认知识点编辑 -> edit_history表自动记录 -> 可回滚
7. [预留] 知识产品生产 -> knowledge_usage_log追踪 -> 优化知识库
8. [预留] 问答助手 -> 三层标签精准检索 -> 按access_level控制分发

## 文件夹结构
data/
  |- pending/      待处理文件放入口
  |- processing/   预处理后的文件
  |- completed/    提取完成归档
  |- failed/       提取失败隔离
  |- database/     SQLite数据库

## 安全：Fernet加密Key | 白名单路径 | 每日费用上限 | 强制HTTPS

## 技术注意事项
- bat必须GBK编码+CRLF换行
- api_server.py用Response返回HTML(不用render_template)
- review.html不能有emoji字符,JS用ES5 Promise语法
- R1模型不支持temperature参数,超时需设300秒
- R1模型不设人为max_tokens上限,通过控制输入分段长度(4000字/段)来间接控制输出
- AI分类建议使用V3模型(deepseek-chat),不需要R1
- 标签过滤规则在api_server.py中硬编码(黑名单+正则)
- 已确认知识点的任何编辑自动记录到edit_history表
- 分类体系支持动态新增(含一级分类)
- 三层标签清单由tag_config.py统一管理,Prompt动态读取,新增领域不改代码
- 横向拓展只需在tag_config.py的A组增加标签+在categories表新增分类

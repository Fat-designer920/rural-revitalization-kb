# 系统架构总览

## 基本信息
- 当前版本：v1.1.0
- 封装方式：便携版（绿色免安装）
- 运行环境：Windows + Python 3.8+
- AI引擎：DeepSeek API（提取引擎使用R1推理模型，分类建议使用V3模型）
- 本地存储：SQLite
- 操作界面：Flask本地Web应用
- 操作方式：双击.bat文件
- 代码仓库：https://github.com/Fat-designer920/rural-revitalization-kb （公开，可直接读取）

## 架构

用户操作层(.bat文件, GBK编码, 调用Python前chcp 65001)
  |
Python脚本层(scripts/, UTF-8编码)
  |- config_wizard.py - tkinter配置向导
  |- setup.py - 一键初始化
  |- file_reader.py - 多格式读取(PDF/Word/Excel/图片/文本)
  |- deepseek_client.py - DeepSeek API封装(费用控制+3次重试+R1模型适配)
  |- preprocessor.py - 智能预处理(AI重命名+标签)
  |- extractor.py - 知识点提取(R1深度推理+MD5去重+failed隔离+AI分类建议)
  |- api_server.py - Flask审核界面(编辑历史+分类管理+标签过滤+AI建议+全文搜索)
  |- db_manager.py - 数据库CRUD(含编辑历史+分类新增+架构建议+全文搜索)
  |- check_system.py - 系统检查
  |- prompts/prompt_templates.py - 10个Prompt(5个提取Prompt已强化)
  |- migrate_v101_to_v110.py - 数据库迁移脚本
  |
数据层(SQLite, 9张表)
  |- categories(27+条,可动态新增) | source_files | knowledge_points
  |- knowledge_versions(v1.1.0预留) | architecture_suggestions(v1.1.0激活)
  |- edit_history(v1.1.0新增) | operation_logs | api_call_logs
  |- notion_sync_log(v1.2.0)

## 数据流
1. data/pending/ -> preprocessor(AI重命名) -> data/processing/
2. extractor(R1提取+MD5去重) -> SQLite(待审核) -> data/completed/
3. 提取完成后 -> AI分类建议分析(V3) -> architecture_suggestions表
4. 提取失败的文件 -> data/failed/(隔离,不堵塞队列)
5. api_server(审核界面) -> 人工审核 -> SQLite(已确认)
6. 已确认知识点编辑 -> edit_history表自动记录 -> 可回滚

## 文件夹结构
data/
  |- pending/      待处理文件放入口
  |- processing/   预处理后的文件(AI重命名后)
  |- completed/    提取完成的文件归档
  |- failed/       提取失败的文件隔离区
  |- database/     SQLite数据库

## 安全：Fernet加密Key | 白名单路径 | 每日费用上限 | 强制HTTPS

## 技术注意事项
- bat必须GBK编码+CRLF换行
- api_server.py用Response返回HTML(不用render_template)
- review.html不能有emoji字符,JS用ES5 Promise语法
- Python输出前需chcp 65001 + PYTHONIOENCODING=utf-8
- R1模型不支持temperature参数,超时需设300秒
- R1模型费用约为普通模型4-8倍,建议每日上限设100-150元
- AI分类建议使用V3模型(deepseek-chat),不需要R1
- 标签过滤规则：后端过滤纯数字/百分比/公文操作词/过于宽泛的词,长度2-14字

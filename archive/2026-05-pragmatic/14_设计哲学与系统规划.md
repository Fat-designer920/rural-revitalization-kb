# 设计哲学与系统规划

> 对标: Apple HIG + Google Material + MUJI 无印良品 + 中国宋代美学
> 目标: 乡镇干部打开产品,3秒内感觉"这产品懂我"

---

## 一、设计哲学: 三家合一

### Apple HIG — 清晰、顺从、深度

| 原则 | 我们的应用 |
|------|-----------|
| **内容驱动** | 答案本身是主角,不是UI框架。去掉一切不必要的装饰 |
| **留白即语言** | 大段空白不是浪费,是让内容呼吸。卡片间距≥24px |
| **字体即界面** | PingFang SC的Regular/Medium/Semibold三级就够了 |
| **半透明材质** | 毛玻璃效果(backdrop-filter)用于导航栏,暗示层级 |
| **触觉反馈** | 按钮hover有微妙缩放(transform:scale(0.98)),点击有反馈 |

### Google Material Design — 系统、一致、可访问

| 原则 | 我们的应用 |
|------|-----------|
| **Design Token** | 颜色/字体/间距/圆角全部CSS变量,禁止硬编码 |
| **8dp网格** | 所有间距是8的倍数(8/16/24/32/48/64px) |
| **海拔系统** | 0/1/2/4/8/16px五个阴影层级,表示内容层级 |
| **动效有意义** | 过渡动画不是装饰,是告诉用户"你从哪来,到哪去" |
| **可访问性** | WCAG AA最低标准,对比度≥4.5:1,最小字号14px |

### MUJI 无印良品 — 这就够了

| 原则 | 我们的应用 |
|------|-----------|
| **"空"的美学** | 不是没有东西,是把不需要的东西去掉。白色背景,极细分割线 |
| **自然材质感** | 不是真的木头,是暖灰色(#F5F0E8)模拟纸张的温暖 |
| **无品牌标识** | 不放大logo,不强调"我们",让用户关注内容 |
| **克制的色彩** | 主色只有3个: 深绿(可信赖)+ 金色(温暖)+ 暖灰(纸张) |
| **减法原则** | 每加一个新元素,必须先删一个旧元素 |

### 中国宋代美学 — 清新淡雅

| 原则 | 我们的应用 |
|------|-----------|
| **留白** | 宋画大段空白不是没画完,是给观者想象空间。页面留白≥40% |
| **水墨色系** | 不是纯黑,是墨分五色: 焦/浓/重/淡/清 → #1A1A1A/#333/#666/#999/#CCC |
| **线条极简** | 宋瓷无纹饰。分割线只用0.5px的#E5E5EA,不用粗边框 |
| **克制装饰** | 不用渐变、不用阴影堆叠、不用动画炫技 |
| **文人气质** | 字体间距宽松(letter-spacing:0.02em),行距舒适(line-height:1.75) |

## 二、双线协作与验证机制

### 协作模型

```
Track B(外部工具)            Track A(内部设计)
      │                           │
      ├─ Water.css ───────────────→ 即时美化基线
      ├─ Chinese Typography ──────→ 字体标准
      ├─ Pico.css ────────────────→ 组件库
      ├─ Open Props ──────────────→ Design Token
      ├─ Service Worker ─────────→ 离线能力
      ├─ WeChat JSSDK ───────────→ 微信生态
      └─ accessibility-checker ──→ 质量门禁
                                          │
      ┌───────────────────────────────────┘
      ▼
   设计系统规范(Design System Spec)
      │
      ├─ 颜色Token: --color-primary: #1a5632 等20个
      ├─ 字体Token: --font-body: 16px/1.75 PingFang SC 等10个
      ├─ 间距Token: --space-xs/sm/md/lg/xl/2xl = 4/8/16/24/32/48/64px
      ├─ 圆角Token: --radius-sm/md/lg = 4/8/16px
      ├─ 阴影Token: --shadow-none/low/medium/high = 5级海拔
      └─ 组件清单: 按钮/输入框/卡片/导航/标签/对话框/表格等18个组件
```

### 验证标准 — "这产品懂我"五维度

| 维度 | 标准 | 如何验证 |
|------|------|---------|
| **视觉舒适** | MUJI+宋代美学 | 做减法测试: 随机删掉一个元素,页面更好了吗? |
| **操作流畅** | Apple HIG | 核心任务<30秒完成,中间不超过3步 |
| **信息清晰** | Material Design | 用户3秒内能回答"这个页面是干什么的" |
| **加载感知** | Google RAIL | 首屏<1.5秒,交互<100ms反馈 |
| **无障碍** | WCAG AA | 对比度≥4.5:1, 字号≥14px, 键盘可操作 |

### 验证方法

```
自动化验证(每次commit):
  ├─ accessibility-checker: WCAG 2.1 AA 11+规则
  ├─ Lighthouse: Performance/Accessibility/Best Practices/SEO
  └─ size-limit: 每页面总载荷<200KB

人工验证(每个Phase完成):
  ├─ 乡镇干部模拟测试: 老唐找一个真实乡镇干部试用
  ├─ 3G网络测试: Chrome DevTools throttling → Slow 3G
  ├─ 微信内置浏览器测试: 在微信里打开所有页面
  ├─ 320px手机测试: iPhone SE尺寸验证
  └─ 老唐目测: "这个页面看起来舒服吗?"

设计审查(design review):
  ├─ 减法审查: 能不能再删一个元素?
  ├─ 留白审查: 空白区域是否≥40%?
  ├─ 层级审查: 信息架构是否≤3层?
  └─ 一致审查: 所有页面是否用同一个token?
```

## 三、我想到你可能没想到的(8项补充)

### 1. 空状态设计 — 用户第一次看到的

**为什么重要**: 新用户打开QA页面,还没有任何问答历史。这个"空"的瞬间决定了用户的去留。

**MUJI式空状态**: 
```
┌──────────────────────────────┐
│                              │
│         🤖 (可选小图标)       │
│                              │
│    有什么政策问题,尽管问我    │
│                              │
│   ┌──────────────────────┐   │
│   │ 例如: 增减挂钩项目...  │   │  ← 灰色文字,点击自动填入
│   └──────────────────────┘   │
│                              │
│   或直接按住说话 🎤           │
│                              │
└──────────────────────────────┘
```
没有长篇介绍,没有引导教程。一个输入框+两个提示+大量留白。

### 2. 加载状态 — 等待的时刻

**为什么重要**: 13秒的QA响应时间。用户不等。需要让等待"感觉"快。

**方案**:
- 不是转圈菊花,是骨架屏(skeleton screen): 灰色矩形块模拟即将出现的内容
- 不是进度条,是"正在检索相关政策…" → "正在整理答案…" → "正在核实来源…" 三阶段文案
- MUJI式: 一个淡淡的呼吸动画(opacity 0.3→0.6→0.3),告诉用户"还活着"

### 3. 错误状态 — 出问题的时候

**为什么重要**: 网络中断、API超时、检索失败。出问题时用户最容易流失。

**方案**:
- 不是红叉报错,是温和的"稍等,正在重试…"
- 离线时: "当前离线,以下为最近缓存的内容"(不吓人)
- API失败: "AI正在休息,先看看这些相关知识点"(降级体验,不是空白)
- 永远给用户一个"下一步": 刷新/看缓存/换问题

### 4. 过渡动画 — 不是装饰,是导航

**为什么重要**: Apple的动画哲学: 动画告诉用户"你从哪来,到哪去"。

**方案**:
- 页面切换: 不是跳转,是200ms淡入(fadeIn)
- 答案展开: 不是突然出现,是300ms从卡片顶部滑出
- 按钮点击: 150ms缩放(1.0→0.97→1.0)给触觉暗示
- 列表加载: 逐条150ms交错淡入(staggered),不是一起出现
- **克制**: 总共不超过4种动画,每种≤300ms

### 5. 声音设计 — 几乎听不到,但感觉到了

**为什么重要**: iPhone的"咔嗒"解锁声、微信的"嗖"发送声——不是必须的,但有就是高级感。

**方案**:
- 不是音乐,是极短的反馈音(50-100ms)
- 发送问题 → 一个细微的"嗒"(模仿纸笔接触)
- 答案到达 → 一个细微的"叮"(比微信轻)
- 错误 → 无声音,只有视觉变化(不惊吓用户)
- 可关闭: 设置里有"声音反馈"开关,默认开启

### 6. 内容节奏 — 不是一股脑全显示

**为什么重要**: 一个QA答案可能有500字。一次性全显示=用户不读。

**方案**:
- 直接回答(200字) → 先显示
- 政策依据 → "展开查看"折叠
- 操作步骤 → 每条一个卡片,逐条展开
- 风险提示 → 折叠,只在"有风险"时才显示(而不是显示一个空的"无风险")
- 延伸思考 → 3条,折叠,点击展开
- **渐进式信息披露**: 用户不需要的信息就不显示,想看了再展开

### 7. 个性化痕迹 — 让用户感觉"这是我的"

**为什么重要**: MUJI的空不是冷漠,是"给你留空间"。

**方案**:
- 查询历史: 不是列表,是时间线(像对话)
- 常用问题: 自动识别,显示在首页"你可能想问"
- 上次看的课程: 记住进度,不是从头开始
- **不做的事**: 不用用户头像、不用用户名、不用积分/等级/勋章(那是游戏化,不是中国风)

### 8. 包容性设计 — 不是给"残障人士"的,是给所有人的

**为什么重要**: 40-55岁乡镇干部的老花眼不是"残障",是"人类正常的衰老过程"。适老化设计惠及所有人。

**方案**:
- 字号三档: 标准(16px)/大(20px)/特大(24px),一键切换
- 不是单独的老花模式,是所有人都可以调的设置
- 高对比度模式: 不是"黑底白字",是墨色加深(#1A1A1A→#000) + 背景变白
- **核心洞察**: 给老花眼的大字号,年轻人晚上躺床上看手机也会用

## 五、Track A + Track B 衔接细节

### 每个工具整合后的验证

| 工具 | 谁整合 | 谁验证 | 验证方式 |
|------|--------|--------|---------|
| Water.css | Track B | Track A | 6页面视觉一致性+加载增量<2KB |
| Typography CSS | Track B | Track A | 中文字体渲染+行高+间距实测 |
| WeChat JSSDK | Track B | Track A | 微信内打开+分享卡片+语音识别 |
| Pico.css | Track B | Track A | 130+CSS变量覆盖+与design-system不冲突 |
| Open Props | Track B | Track A | Token命名规范+与现有颜色无冲突 |
| Service Worker | Track B | Track A | 离线测试+缓存更新+离线提问队列 |
| a11y-checker | Track B | Track A | CI自动运行+0 violation通过 |

### 设计系统是双线的共同语言

Track A和Track B不会互相覆盖,因为它们操作的是不同的层:
- **Track B**(工具层): 引入外部CSS/JS文件,不修改现有HTML结构
- **Track A**(设计层): 基于设计系统规范,用CSS变量控制视觉,不修改Track B的工具文件
- **冲突解决**: 如果Pico.css的颜色与我们设计系统的颜色冲突,用CSS变量覆盖

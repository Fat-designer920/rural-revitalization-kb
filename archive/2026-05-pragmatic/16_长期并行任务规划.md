## 14项可并行任务 → 4条流水线

### 流水线A: 内容生产(数据持续流入)

```
A1 爬虫日循环(crawler_scheduler.run_scheduled)
   ↓ 产出: 新鲜政策文档
A2 文件→提取(预处理器→双模型提取→QC)
   ↓ 产出: 新KP入库
A3 关系扫描(relation_analyzer.scan_incremental)
   ↓ 产出: 新关系边
A4 知识图谱更新(KnowledgeGraph.build)
   ↓ 产出: 新实体+边
A5 精品判定(premium_judge)
   产出: 精品KP池扩增(当前46→目标200+)
```

### 流水线B: 质量保障(持续验证)

```
B1 QA评测基线(benchmark_system.run_benchmark)
   产出: 首次50查询基准分
B2 引用验证(citation_verifier.verify_all)
   产出: 所有KP的引用可信度报告
B3 对抗测试(adversarial_tester.run_attack_suite)
   产出: QA系统鲁棒性评分(0-100)
B4 安全扫描(semantic_check全量KP)
   产出: 安全隐患报告
B5 保鲜扫描(freshness_monitor)
   产出: 过期KP标记+更新建议
```

### 流水线C: UI改造(用户可见)

```
C1 设计系统落地(design-tokens+components接入全部6页面)
   产出: 视觉一致性
C2 QA产品页开发(mobile-first,老唐风格,语音+分享+打印)
   产出: 可上线的QA页面
C3 管理后台优化(review.html性能+Tab体验)
   产出: 更流畅的后台
C4 移动端适配(320px-1920px全分辨率)
   产出: 手机可用
```

### 流水线D: 系统运维(持续监控)

```
D1 内存监控(infrastructure_agent,每30秒)
D2 CEO自我提升(每5周期能力检测+自动升级)

```

## 依赖与并行

```
流水线A(内容) ──── 完全独立 ────→ 流水线B(质量) ──→ B的结果反馈给A
     │                                    │
     │                               B2(引用验证)→A3(关系扫描)
     │                               B1(评测)→A5(精品判定)
     │
流水线C(UI) ──── 完全独立 ────→ 不依赖A/B的结果
     │
流水线D(运维) ── 完全独立 ──→ 监控A/B/C的运行状态
```

**4条流水线互不阻塞,可以同时启动。**
